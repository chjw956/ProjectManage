# 기능 세로 슬라이스 구현

기능 하나를 DB부터 화면까지 끝까지 완성한다. 단계별 검사를 통과해야 다음으로 넘어간다.

## 0. 계획 (구현 전에 제시하고 확인받기)

- 대상 기능과 설계서 절 (예: 4.10 WBS·간트 보기)
- 변경할 테이블·API·화면 목록
- 참고 화면이 있으면 `docs/screens/`의 파일명
- 테스트할 핵심 규칙 3~5개
- 계산 로직이 있으면 `calc-rules`, 변경 이력이 있으면 `history-logging` 스킬 적용 여부

## 1. DB

- 스키마 변경은 `db-migration` 스킬을 따른다.
- 시드 데이터(`R__seed_local.sql`, local 프로필 전용)에 화면 확인용 가상 데이터를 추가한다.

## 2. 백엔드

1. 엔티티·리포지토리
2. 서비스 테스트 먼저 작성 → 실패 확인 → 구현 (권한 확인 포함)
3. `record` DTO, 컨트롤러, 입력 검증
4. `@WebMvcTest`로 응답 형태와 403 확인
5. `./mvnw test` 통과

## 3. API 계약

- `/v3/api-docs`에서 엔드포인트 확인
- `docs/api.md`에 엔드포인트, 파라미터, 응답 예시 추가

## 4. 프론트엔드

1. `npm run gen:api`로 타입 재생성
2. `src/api/`에 Query 훅 추가
3. 참고 화면 레이아웃대로 구현. 로딩·빈 상태·에러 상태 포함
4. MSW로 컴포넌트 테스트
5. `npm run lint && npm run typecheck && npm test` 통과

## 5. 마무리

- 변경 요약, 테스트 결과, 남은 TODO
- 커밋 메시지 제안: `feat(<도메인>): <요약>`

## 하지 말 것

- 백엔드 없이 임의 필드로 화면 만들기
- 여러 기능 슬라이스를 한 번에 섞기
- 테스트 실패 상태로 다음 단계 진행
