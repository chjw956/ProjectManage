# 히스토리 자동 기록

## 기록 대상과 이벤트 유형

| 변경 | 사유 필수 | 이벤트 유형 | 요약 예시 |
| --- | --- | --- | --- |
| Task·마일스톤 계획일 변경 | O | SCHEDULE_CHANGED | `수출 승인 서류 작성: 종료 10/30 → 11/14` |
| Task 상태 변경 | 완료 시 X, 그 외 O | STATUS_CHANGED | `대외기관 사전 협의: 진행중 → 완료` |
| 사업 상태·단계 변경 | O | PROJECT_STATUS_CHANGED | |
| 담당자·참여자 변경 | O | MEMBER_CHANGED | `PM: 홍길동 → 김철수` |
| 기준 이벤트 일자 변경 | O | BASE_EVENT_CHANGED | `JV 설립: 2027-03-01 → 미정` |
| 집행 등록 | X | PAYMENT_EXECUTED | `기계 개조 공사 선금 416백만원 집행` |
| 결정 등록 | (배경·이유 필드) | DECISION | 결정 내용 |
| 이슈 발생·해결 | X | ISSUE_OPENED / ISSUE_RESOLVED | |

## 구현 규칙

1. 변경 요청 DTO에 `reason` 필드를 두고, 사유 필수 항목은 Bean Validation으로 막는다 (400).
2. 이벤트 기록은 `HistoryRecorder.record(...)` 한 곳에서만 한다. 각 서비스에서 event를 직접 만들지 않는다.
3. **변경과 이벤트 기록은 같은 트랜잭션**에서 처리한다. 하나만 성공하면 안 된다.
4. 이벤트에는 `before`, `after`(JSONB), `reason`, `actor`, `source`(MANUAL/AUTO), 대상 엔티티 타입·ID를 남긴다.
5. 값이 실제로 바뀌지 않았으면 이벤트를 만들지 않는다.
6. 이벤트는 수정·삭제하지 않는다. 잘못 기록됐으면 정정 이벤트를 추가한다.
7. 일정 변경이 사업 단위 결정이면(예: 범위 축소) 결정 로그로 등록하도록 화면에서 안내한다.

## 프론트엔드

- 사유 필수 변경(간트 막대 드래그 포함)은 저장 전에 사유 입력 모달을 띄운다.
- 모달에는 변경 전 → 후 값을 보여준다.

## 테스트 필수 케이스

- [ ] 사유 없이 일정 변경 → 400, 데이터와 이벤트 모두 변경 없음
- [ ] 일정 변경 → 같은 트랜잭션에서 event 1건 생성, before/after 정확
- [ ] 같은 값으로 저장 → 이벤트 생성 안 됨
- [ ] 이벤트 저장 실패 시 원래 변경도 롤백
