# 프로젝트·정부사업 트래킹 플랫폼 설계서 (초안)

Oct 19, 2026 · @Jiwon Choi

## 1. 개요

사내 프로젝트와 정부사업의 진행 상황·의사결정·산출물을 한곳에 기록해, 누가 중간에 투입되어도 맥락을 빠르게 파악하고 전체 현황을 한 화면에서 보는 플랫폼을 구축한다.

### 1.1 배경 및 문제

- 사업 정보가 메일, 메신저, 개인 PC, 그룹웨어 결재 문서에 흩어져 있어 현황 파악에 시간이 오래 걸린다.
- 담당자 변경·중간 투입 시 "왜 이렇게 결정됐는지"가 문서로 남아 있지 않아 히스토리가 사람에게 의존한다.
- 정부사업은 중간·연차 보고, 사업비 정산, 협약 변경 등 의무 일정이 많아 누락 시 불이익이 크다.
- 경영진·팀장 보고를 위해 매번 현황을 수작업으로 취합한다.

### 1.2 목표

| 목표 | 측정 기준 (제안치) |
| --- | --- |
| 중간 투입자의 빠른 맥락 파악 | 사업 홈 + 온보딩 브리핑만으로 30분 내 현황 설명 가능 |
| 현황의 신속한 파악 | 전체 사업 상태를 1개 화면에서 확인, 보고 취합 시간 50% 단축 |
| 정부사업 의무 이행 | 보고·정산 기한 누락 0건 |
| 기록의 지속성 | 주간 업데이트 작성률 90% 이상 |

### 1.3 범위

- 포함: 사내 프로젝트(IT·AX·공정개선 등), 정부 R&D 및 지원사업, 대외 인증 과제
- 제외: 회계·ERP 시스템 대체, 상세 WBS 수준의 공정 일정 관리, 인사 평가

## 2. 설계 원칙

플랫폼이 실제로 쓰이려면 "기록은 쉽게, 읽기는 빠르게"가 핵심이며, 아래 6가지 원칙을 모든 기능 설계의 기준으로 삼는다.

1. **1사업 1홈**: 사업별로 단 하나의 요약 페이지(사업 홈)가 최신 상태의 기준이 된다.
2. **결정은 이유와 함께**: 무엇을 했는지보다 왜 그렇게 결정했는지를 남긴다. 중간 투입자가 가장 알기 어려운 정보이기 때문이다.
3. **상태는 신호로, 서술은 최소로**: 정상·주의·위험 3단계와 진척률·D-day로 현황을 표현한다.
4. **입력 부담 최소화**: 담당자는 주 1회 5분 내외 정형 폼만 작성하고, 회의록·결재·메일은 자동 수집한다.
5. **원본은 링크, 요약은 플랫폼**: 문서를 복제하지 않고 원본 위치(Outline Wiki, 그룹웨어, 공유 드라이브)를 연결한다.
6. **AI는 보조, 기록의 원천은 사람**: LLM은 요약·브리핑·질의응답을 돕되, 결정과 상태 변경은 담당자가 확정한다.

## 3. 사용자 및 핵심 시나리오

주 사용자는 4개 그룹이며, 설계의 최우선 대상은 "중간 투입자"다.

| 사용자 | 주요 니즈 | 주로 보는 화면 |
| --- | --- | --- |
| 중간 투입자 (신규 담당·지원 인력) | 지금까지의 흐름, 주요 결정의 이유, 당장 할 일 | 온보딩 브리핑, 타임라인, 결정 로그 |
| 사업 담당자 (PM) | 진행 기록, 일정·이슈 관리, 보고서 작성 | 사업 홈, 주간 업데이트, 이슈 레지스터 |
| 팀장·경영진 | 전체 사업 상태, 위험 사업 조기 파악 | 포트폴리오 대시보드 |
| 정부사업 관리자 (연구지원·재무) | 보고·정산 기한, 사업비 집행률, 증빙 | 정부사업 모듈, 의무 일정 캘린더 |

### 시나리오 A. 진행 중인 정부사업에 중간 투입

1. 사업 홈에서 "온보딩 브리핑"을 연다.
2. 사업 목적, 지금까지의 주요 결정 5건, 현재 단계, 미결 이슈, 꼭 읽을 문서, 만나야 할 사람을 확인한다.
3. 궁금한 점은 "협약 변경은 왜 했어?" 처럼 자연어로 질문하고, 답변의 근거 문서 링크로 원본을 확인한다.

### 시나리오 B. 주간 현황 보고

1. 담당자가 금요일에 주간 업데이트 폼(한 일·할 일·이슈·상태)을 작성한다.
2. 플랫폼이 타임라인과 대시보드에 자동 반영하고, 팀 단위 주간 보고서 초안을 생성한다.
3. 팀장은 대시보드에서 "주의·위험" 사업만 골라 확인한다.

### 시나리오 C. 정부사업 중간보고 준비

1. 보고 기한 30일·14일·7일 전 담당자와 관리자에게 알림이 간다.
2. 해당 기간의 타임라인·산출물·사업비 집행 현황을 모아 보고서 초안 자료를 생성한다.
3. 제출 완료 시 의무 일정이 "완료"로 바뀌고 제출본 링크가 남는다.

## 4. 기능 설계

기능은 "현황 파악(4.1\~4.2)", "히스토리 파악(4.3\~4.5)", "정부사업 관리(4.6)", "기록·활용 자동화(4.7\~4.9)"의 4개 축으로 구성한다.

| ID | 기능 | 핵심 내용 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 포트폴리오 대시보드 | 전체 사업 상태 1화면 | 1단계 |
| F2 | 사업 홈 | 사업별 1페이지 요약 | 1단계 |
| F3 | 히스토리 타임라인 | 사업의 모든 이벤트 시간순 | 1단계 |
| F4 | 결정 로그 | 결정·배경·대안·결정자 | 1단계 |
| F5 | 이슈·리스크 레지스터 | 미결 이슈와 대응 현황 | 1단계 |
| F10 | WBS·간트 보기 | 공정·세부 Task별 계획 대비 실제 일정 | 1단계 |
| F6 | 정부사업 모듈 | 협약·의무 일정·사업비·증빙 | 2단계 |
| F11 | 예산 집행 현황 | 선금·중도금·잔금 집행 일정, 월별 소계·누계 | 2단계 |
| F7 | 주간 업데이트 | 정형 폼, 보고서 자동 생성 | 2단계 |
| F8 | 온보딩 브리핑 | 중간 투입자용 자동 요약 | 3단계 |
| F9 | 자연어 질의 | 사내 LLM 허브 연동 Q&A | 3단계 |

### 4.1 포트폴리오 대시보드 (F1)

- 사업별 카드 또는 표: 사업명, 유형(사내/정부), 단계, 상태 신호등, 진척률, 다음 마일스톤과 D-day, 열린 위험 이슈 수, 최근 업데이트일
- 필터: 유형, 담당 부서, 상태, 담당자
- 경고: 7일 이상 미갱신 사업, 기한 14일 이내 정부사업 의무 일정, "위험" 상태 사업을 상단에 고정

### 4.2 사업 홈 (F2)

한 페이지에서 "이 사업이 무엇이고 지금 어디쯤인지"를 답한다.

- 상단: 한 줄 요약, 목표·KPI, 현재 단계, 상태 신호등, 기간
- 사람: 담당자, 참여자, 승인권자, 외부 협력사·전담기관 담당자
- 일정: 마일스톤 타임라인(완료/진행/예정)
- 최근 동향: 최근 결정 3건, 열린 이슈, 최근 주간 업데이트
- 링크: 핵심 문서(계획서, 협약서, 회의록, 산출물) 원본 위치

### 4.3 히스토리 타임라인 (F3)

- 이벤트 유형: 착수, 회의, 결정, 변경(범위·일정·예산·담당자), 산출물, 보고·제출, 이슈 발생·해결
- 각 이벤트는 날짜, 한 줄 요약, 작성자, 근거 문서 링크를 가진다.
- 유형·기간·키워드 필터와 "주요 이벤트만 보기" 토글을 제공한다.

### 4.4 결정 로그 (F4)

중간 투입자의 "왜?"에 답하는 핵심 기능이다. 항목 구성은 다음과 같다.

- 결정 일자, 결정 내용, 배경(당시 상황), 검토한 대안, 선택 이유, 결정자, 영향 범위, 근거 문서
- 상태: 유효 / 변경됨(후속 결정 링크) / 폐기

### 4.5 이슈·리스크 레지스터 (F5)

- 이슈명, 등급(상·중·하), 담당자, 발생일, 목표 해결일, 대응 방안, 상태
- 해결 시 타임라인에 "이슈 해결" 이벤트로 자동 기록

### 4.6 정부사업 모듈 (F6)

- 협약 정보: 과제번호, 사업명, 전담기관, 협약 기간, 정부출연금·기업부담금, 참여기관
- 의무 일정 캘린더: 협약 체결, 중간·연차·최종 보고, 사업비 정산, 성과 보고(사업 종료 후 추적 기간 포함), 기한 30·14·7일 전 알림
- 사업비: 비목별 예산 대비 집행액·집행률, 증빙 첨부 체크리스트
- 협약 변경 이력: 변경 사유, 승인일, 변경 전후 내용
- 성과물 관리: 특허, 논문, 시제품, 인증 등 성과 지표 대비 실적

### 4.7 주간 업데이트 (F7)

- 정형 폼 4칸: 이번 주 한 일, 다음 주 할 일, 이슈·요청 사항, 상태 변경(있을 때만)
- 제출 즉시 타임라인·대시보드 반영, 팀 단위 주간 보고서 초안 자동 생성
- 금요일 오후 미작성자 리마인드

### 4.8 온보딩 브리핑 (F8)

사업 홈의 "처음 오셨나요?" 버튼으로 생성되는 1페이지 요약이다.

- 이 사업은 무엇인가 (목적·범위·기간)
- 지금까지의 흐름 (주요 이벤트·결정 Top 5)
- 현재 상태와 다음 마일스톤
- 알아야 할 미결 사항
- 꼭 읽을 문서 5개, 만나야 할 사람
- 생성 근거(타임라인·결정 로그 항목) 링크를 함께 표시하고, 담당자가 검수한 버전을 고정본으로 저장할 수 있다.

### 4.9 자연어 질의 (F9)

- 사내 LLM 허브에서 "OO사업 다음 보고 기한 언제야?", "협약 변경은 왜 했어?" 같은 질문에 답한다.
- 플랫폼 데이터와 연결 문서를 근거로 답하고, 근거 링크를 항상 함께 제시한다.
- 사용자 권한 밖의 사업 정보는 답변에서 제외한다.

### 4.10 WBS·간트 보기 (F10)

사업을 "공정 → 세부 Task" 2단계로 나누고, 계획 대비 실제 일정을 간트 차트로 한 화면에서 비교한다.

- 구조: 사업 > 공정(작업 그룹) > 세부 Task. 공정 행에는 조건·기간 요약(공사 여부, 금액, 계획·실제 기간)을 함께 표시한다.
- 표 열: 공정/세부 Task, 담당 부서, 담당자, 상태(예정·진행중·완료·지연), 진행률. "표시 열" 설정으로 열 구성을 바꿀 수 있다.
- 간트 막대: Task마다 계획(테두리)과 실제(채움) 막대를 2줄로 표시하고, 오늘 날짜에 기준선을 긋는다.
- 화면 조작: 주 단위 / 기간 축소 전환, 이전·오늘·다음 이동, 전체 펼치기·접기, 목록 / 간트 보기 전환
- 마일스톤 바: 상단에 주요 마일스톤을 유형별 색상 칩(명칭·날짜)으로 표시하고, 클릭하면 간트의 해당 일자로 이동한다.
- 검색·필터: 작업·공정·담당자 검색, 부서·상태 드롭다운, 빠른 필터(전체, 내 작업, 우리 부서, 지연, 마감 임박, 7일 이내), 결과 건수 표시
- 편집: 공정별 "+ 작업" 추가, 드래그로 순서 변경, 막대 드래그로 일정 조정
- 히스토리 연동: 일정 변경 시 사유 입력을 필수로 받고, 타임라인에 "일정 변경" 이벤트(변경 전후 날짜·사유)를 자동 기록한다. 중간 투입자가 "왜 일정이 밀렸는지"를 추적할 수 있다.
- 현황 연동: Task 진행률이 공정·사업 진척률로 자동 집계되어 대시보드와 사업 홈에 반영되고, 지연 Task는 상태 판단(6.2)에 반영된다.
- 진척률 산정(제안): Task 진행률을 계획 기간으로 가중 평균한다.

### 4.11 예산 집행 현황 (F11)

WBS의 공정과 별개로 선금·중도금·잔금 등 집행 항목의 일정과 금액을 관리하고, 계획 대비 집행률을 월 단위로 추적한다.

**기준 이벤트 설정**

- 사업별로 집행 시기를 가르는 기준 이벤트(예: JV 설립)를 예정일과 메모로 등록한다. 확정 전이면 비워 둘 수 있고, "미정으로 되돌리기"를 지원한다.
- 집행 시기는 실집행일(없으면 계획일)이 기준일보다 앞서면 "설립 전·선투자", 같거나 뒤면 "설립 후"로 자동 분류한다.
- 기준일을 바꾸면 변경 사유를 받아 결정 로그와 타임라인에 기록한다.

**조회·필터**

- 항목 검색, 구분(선금·중도금·잔금), 집행 주체(자사·상대사·양사 공동·법인 등), 시기(설립 전·후), 상태(예정·집행·지연) 필터와 결과 건수
- 목록 / 일정 보기 전환
- 입력 점검 배너: 입력 확인 필요, 계획금액 미정, 집행 주체 미지정 건수를 표시하고, 입력이 불완전한 금액은 합계에서 제외한다.

**요약 카드** (조회 조건 기준, 단위 백만원)

- 계획 총액, 집행 총액, 집행률(집행 총액 ÷ 계획 총액), 지연 건수(계획일이 지났는데 미집행)

**일정 보기**

- 구분별 그룹(건수 배지)과 항목 행: 항목명, 상태 배지, 계획금액·집행 주체·시기
- 타임라인에 계획일(마름모)과 실집행일을 다른 표식으로 찍고, 오늘 기준선과 기준 이벤트 세로 점선·라벨을 함께 표시한다.
- 주 단위 / 기간 축소, 이전·오늘·다음 이동, 전체 펼치기·접기

**월별 소계**

- 열: 월, 계획금액, 집행금액, 누적 집행률(막대 + %), 마지막 행 합계
- 계획은 계획일의 월, 집행은 실집행일의 월에 집계하고, 기준 이벤트가 있는 달은 라벨과 함께 강조한다.

**월별 누계**

- 열: 월, 누계 계획금액, 누계 집행금액, 잔여, 누계 집행률
- 잔여 = 누계 계획금액 − 누계 집행금액. 계획보다 많이 집행했으면 음수로 표시한다.

**연동**

- 집행 등록 시 타임라인에 "집행" 이벤트(금액·증빙 링크)를 자동 기록한다.
- 지연 건수는 사업 상태 판단(6.2)과 대시보드에 반영한다.
- 정부사업은 집행 항목을 정부사업 모듈(F6)의 비목과 연결해 비목별 집행률에도 함께 집계한다.
- 금액 정보는 PM·재무·승인권자만 조회하고, 그 외에는 집행률만 노출한다.

## 5. 데이터 모델

모든 기록은 "사업(Project)"에 연결되며, 타임라인은 결정·이슈·문서·주간 업데이트에서 이벤트를 모아 보여주는 구조다.

| 엔티티 | 주요 필드 | 관계 |
| --- | --- | --- |
| Project (사업) | 사업ID, 사업명, 유형(사내/정부), 단계, 상태, 진척률, 시작·종료일, 한 줄 요약, 보안등급 | 모든 엔티티의 상위 |
| Member (참여자) | 사용자ID, 역할(PM·참여·승인·외부), 투입·이탈일 | Project N:M User |
| Milestone (마일스톤) | 명칭, 유형(색상), 계획일, 실제일, 상태 | Project 1:N |
| Task (WBS 항목) | 상위 공정ID, 명칭, 담당 부서, 담당자, 계획 시작·종료일, 실제 시작·종료일, 상태, 진행률, 정렬 순서, 공정 조건(공사 여부·금액) | Project 1:N, 공정→Task 자기참조 |
| BaseEvent (기준 이벤트) | 명칭(예: JV 설립), 예정일(미정 허용), 메모, 변경 이력 | Project 1:N |
| Payment (집행 항목) | 항목명, 구분(선금·중도금·잔금), 집행 주체, 계획일, 계획금액, 실집행일, 집행금액, 상태, 시기 분류(자동), 증빙 링크, 입력 점검 플래그 | Project 1:N, BaseEvent 참조, BudgetLine 연결(정부사업) |

| Decision (결정) | 일자, 내용, 배경, 대안, 선택 이유, 결정자, 상태, 후속 결정ID | Project 1:N, Event 1:1 |
| Issue (이슈·리스크) | 제목, 등급, 담당자, 발생일, 목표일, 대응 방안, 상태 | Project 1:N |
| Document (문서 링크) | 제목, 유형, 원본 URL, 등록일 | Project·Event·Decision N:M |

## 6. 운영 프로세스 및 기록 규칙

플랫폼의 가치는 기록의 꾸준함에서 나오므로, 기록 시점과 상태 판단 기준을 규칙으로 정한다.

### 6.1 운영 주기

| 주기 | 활동 | 담당 |
| --- | --- | --- |
| 수시 | 결정·변경·이슈 발생 시 기록 (결정은 2영업일 이내) | 사업 담당자 |
| 주간 (금) | 주간 업데이트 작성, 주간 보고서 자동 생성 | 사업 담당자 |
| 월간 | 포트폴리오 리뷰, 주의·위험 사업 점검 | 팀장, DA 파트 |
| 단계 전환 시 | 단계 회고, 사업 홈 요약 갱신 | 사업 담당자 |
| 담당자 변경 시 | 인수인계 체크리스트 완료, 온보딩 브리핑 검수 | 전임·후임 담당자 |
| 사업 종료 시 | 최종 회고, 교훈 기록, 아카이브 전환 | 사업 담당자 |

### 6.2 상태 판단 기준

| 상태 | 기준 (제안) |
| --- | --- |
| 정상 | 마일스톤 지연 없음, 상급 이슈 없음 |
| 주의 | 마일스톤 2주 이내 지연 또는 상급 이슈 1건 이상, 또는 14일 이상 미갱신 |
| 위험 | 마일스톤 2주 초과 지연, 예산·의무 일정 위반 우려, 또는 해결 기한을 넘긴 상급 이슈 |

### 6.3 인수인계 체크리스트

- [ ] 사업 홈 한 줄 요약·현재 단계 최신화
- [ ] 미결 이슈와 결정 대기 사항 정리
- [ ] 진행 중 외부 커뮤니케이션(협력사·전담기관) 현황 기록
- [ ] 핵심 문서 링크 점검
- [ ] 온보딩 브리핑 생성 및 전임자 검수
- [ ] 후임자와 30분 인수인계 미팅 후 타임라인에 기록

### 6.4 기록 작성 규칙

- 제목은 "무엇을 + 결과"로 쓴다. 예: "2차 PoC 범위를 설비예지보전으로 한정"
- 결정에는 반드시 이유와 근거 문서 링크를 남긴다.
- 문서 원본은 정해진 저장소에 두고 플랫폼에는 링크만 등록한다.

## 7. 시스템 아키텍처 및 LLM 허브 연동

플랫폼은 기록의 단일 저장소 역할을 하고, 요약·보고서 생성·질의응답은 사내 LLM 허브의 워크플로우로 처리해 허브화 목표와 같은 방향으로 맞춘다.

&#91;embedded content: 시스템 구성 · 입력 3채널, 플랫폼, 활용 3종, LLM 허브 연동\]

입력 3채널에서 모인 기록이 플랫폼 DB에 쌓이고, LLM 허브는 플랫폼 API와 문서 저장소를 조회해 브리핑·보고서·답변을 만든다. 문서 원본은 저장소에 두고 플랫폼에는 링크만 남긴다.

### 7.1 구축 방식 비교

| 방식 | 장점 | 단점 | 적합 시점 |
| --- | --- | --- | --- |
| 노코드 플랫폼 + Outline Wiki 조합 | 빠른 착수, 기존 사내 자산 활용 | 대시보드·세부 권한 제어에 한계 | 파일럿 (1단계) |
| 오픈소스 PM 도구 커스터마이징 | 기본 기능 확보, 라이선스 비용 낮음 | 정부사업 모듈 별도 개발, 업데이트 대응 부담 | 비교 검토 필요 |
| 자체 개발 (웹 + DB + API) | 요구사항 완전 반영, LLM 허브 연동 용이 | 개발 기간과 인력 소요 | 2단계 이후 |

제안: 1단계는 경량 구성으로 파일럿을 운영해 실제 기록 패턴을 검증하고, 데이터 모델을 유지한 채 2단계에서 자체 개발로 전환한다.

### 7.2 LLM 허브 연동 인터페이스

- 조회 API: 사업 목록·상태, 사업 홈 요약, 타임라인(기간·유형 필터), 결정 로그, 의무 일정
- 등록 API: 주간 업데이트, 회의록 이벤트, 결재 완료 이벤트 (자동 수집용)
- 허브 워크플로우: 온보딩 브리핑 생성, 주간 보고서 생성, 기한 알림 → 허브에 워크플로우로 등록해 자연어로 실행
- 모든 호출은 요청 사용자의 권한을 전달해 권한 밖 데이터를 반환하지 않는다.

## 8. 권한·보안

사업 정보에는 기술·예산·협약 정보가 포함되므로 사업 단위 접근 제어와 보안등급을 기본으로 적용한다.

| 역할 | 조회 | 작성·수정 | 비고 |
| --- | --- | --- | --- |
| 시스템 관리자 (DA 파트) | 전체 | 설정·권한 관리 | 사업 내용 수정은 하지 않음 |
| 사업 PM | 담당 사업 | 담당 사업 전체 | 참여자 초대 가능 |
| 사업 참여자 | 참여 사업 | 업데이트·이슈·문서 링크 | 결정 확정은 PM |
| 팀장·경영진 | 소속 범위 대시보드·사업 홈 | 코멘트 |  |
| 정부사업 관리자 | 정부사업 전체 | 정부사업 모듈 | 사업비·증빙 담당 |

- 보안등급: 일반 / 대외비 / 기밀 3단계. 기밀 사업(국가핵심기술 관련 공정·소재 정보 등)은 참여자 외 조회 불가, 대시보드에는 사업명·상태만 노출한다.
- LLM 연동: 사내 LLM 서비스만 사용하고 외부 API로 데이터를 전송하지 않는다. 질의응답은 질문자의 권한 범위 데이터만 검색한다.
- 계정: 사내 AD 연동 SSO, 퇴사·전보 시 권한 자동 회수
- 감사 로그: 조회·수정·다운로드 이력 보관 (보관 기간은 정보보안 규정에 맞춰 확정)

## 10. 리스크 및 미결 사항

가장 큰 리스크는 기술이 아니라 "기록이 쌓이지 않는 것"이므로, 입력 부담 완화와 보고 체계 연계를 우선 대응한다.

| 리스크 | 영향 | 대응 방안 |
| --- | --- | --- |
| 담당자가 기록하지 않음 | 플랫폼 정보가 낡아 신뢰 상실 | 주간 폼 5분 이내 설계, 주간 보고를 플랫폼 산출물로 대체, 미갱신 경고 |
| 기존 도구와 이중 입력 | 사용 피로, 이탈 | 그룹웨어·회의록 파이프라인 자동 수집, 원본은 링크만 |
| LLM 요약 오류 | 잘못된 맥락 전달 | 근거 링크 필수 표기, 브리핑은 담당자 검수 후 고정 |
| 기밀 정보 노출 | 보안 사고 | 보안등급별 접근 제어, 사내 LLM만 사용, 감사 로그 |
| 외부 협력사 의존 | 유지보수 공백 | 소스·데이터 소유권과 이관 조건을 계약에 명시 |

### 미결 사항

- [ ] 구축 방식 결정: 노코드 플랫폼 활용 / 오픈소스 커스터마이징 / 자체 개발
- [ ] 파일럿 대상 사업 3\~5개 선정 (정부사업 1개 이상 포함)
- [ ] 그룹웨어 결재·메일 연동 가능 범위 확인 (API 제공 여부)
- [ ] 정부사업 관리 주관 부서(연구지원·재무)와 역할 분담 합의
- [ ] 상태 판단 기준과 보안등급 기준의 최종 확정
- [ ] 감사 로그 보관 기간 등 정보보안 규정 검토
